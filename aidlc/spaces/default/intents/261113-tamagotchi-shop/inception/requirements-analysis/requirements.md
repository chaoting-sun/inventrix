# 需求：塔麻可吉主題互動電商前台

依據：`ideation/intent-capture/intent-statement.md`、`ideation/scope-definition/scope-document.md`、`ideation/rough-mockups/wireframes.md`、`requirements-analysis-questions.md`（Q1–Q4），以及程式碼知識庫 `aidlc/spaces/default/codekb/AIDLC-Workshop-v2/`（business-overview.md、architecture.md、code-structure.md）。

## 意圖分析

把現有 Inventrix 顧客端前台改造成塔麻可吉主題、可在 1.5 小時內展示的互動購物體驗：顧客點掉隨機出現的便便賺點數，用點數購買商品，吉祥物隨購物行為反應。資料庫改用 PostgreSQL，並以容器部署到 AWS us-east-1（單一可用區）。

## 功能需求

### FR1 塔麻可吉主題介面
- **FR1.1** 首頁、商品頁、購物車、結帳成功、我的訂單、登入／註冊頁皆使用像素／復古掌機風格。驗收：六個頁面都套用同一主題，無原本的漸層卡片樣式。
- **FR1.2** 每頁右下角固定一台小掌機，內含吉祥物。驗收：任何頁面右下角都看得到掌機。
- **FR1.3** 掌機上有音效開關。驗收：關閉後點便便、加入購物車、結帳都不發聲。
- **FR1.4** 系統設定「減少動態效果」時，動畫改為靜態。驗收：開啟該設定後無動畫播放。

### FR2 便便點數
- **FR2.1** 登入後，每 10 秒在頁面隨機位置冒出一坨便便，畫面上最多 3 坨。驗收：登入停留 30 秒後畫面上有 3 坨，不會超過。
- **FR2.2** 點掉便便得 10 點，便便消失並顯示「+10 ★」，頁首點數即時增加。驗收：點一坨後餘額 +10。
- **FR2.3** 點數存在使用者帳號（資料庫），重新整理或重新登入後仍保留。新帳號從 0 點開始。
- **FR2.4** 未登入時不出現便便，掌機顯示「登入來幫我清便便！」。
- **FR2.5** 點數由伺服器發放與驗證；單一帳號每 10 秒最多入帳 3 坨的點數，避免直接呼叫 API 刷點。

### FR3 點數價格
- **FR3.1** 每個商品的點數價格 = 售價無條件進位成整數（1 元 = 1 點），在商品列表、商品頁、購物車顯示「★ N 點」。

### FR4 購物車（新增）
- **FR4.1** 商品頁可選數量並「加入購物車」；數量上限為庫存，售完時按鈕停用。
- **FR4.2** 未登入也可加入購物車，購物車存在瀏覽器；結帳時才要求登入，登入後回到購物車且內容不變。
- **FR4.3** 購物車頁可調整數量、移除商品，顯示點數合計與目前餘額；購物車為空時顯示「購物車空空的，去逛逛吧！」。
- **FR4.4** 點數不足時結帳按鈕停用，顯示「還差 ★ N，去清便便吧！」。

### FR5 用點數結帳
- **FR5.1** 結帳在單一交易內完成：檢查庫存與點數、扣庫存、扣點、建立訂單；任一失敗則全部不生效並顯示錯誤，購物車不變。
- **FR5.2** 訂單照舊記錄小計、GST、總額（後台照常運作），另外記錄花費點數。
- **FR5.3** 數量必須為正整數，非法數量回傳 400。
- **FR5.4** 結帳成功頁顯示訂單編號、花費點數與剩餘點數，並有「查看我的訂單」「繼續逛逛」。
- **FR5.5** 我的訂單顯示每筆訂單的點數花費。

### FR6 吉祥物反應
- **FR6.1** 加入購物車或點掉便便時，吉祥物播放「開心」動畫與音效。
- **FR6.2** 結帳成功時，吉祥物播放「跳舞」動畫與音樂（掌機與結帳成功頁）。
- **FR6.3** 60 秒沒有互動時吉祥物變成「餓了」，有任何互動後回到待機。

## 非功能需求

- **NFR1** 資料庫改用 PostgreSQL（AWS 上為 RDS for PostgreSQL），移除 SQLite。驗收：完整購物流程在 PostgreSQL 上跑通。
- **NFR2** 前後端以容器部署到 AWS us-east-1，單一可用區，架構保留水平擴展空間（應用程式無本機狀態）。驗收：透過 AWS 網址完成完整購物流程；做不完時以本機展示。
- **NFR3** 機密（資料庫密碼、JWT 金鑰）由環境變數或 Secrets Manager 提供，不寫死在程式；容器映像不得包含 `*.pem`、`*.db`、`setup_info.txt`。
- **NFR4** 只支援桌機瀏覽器（最新版 Chrome）。
- **NFR5** 便便、按鈕可用鍵盤操作，便便的螢幕閱讀器標籤為「清掉便便，加 10 點」。
- **NFR6** 測試採 Minimal 策略：每個功能需求至少一個測試，涵蓋點數入帳、點數不足、結帳交易回滾。

## 限制

- 時程：1.5 小時內成果發表；價值優先（介面 → 點數 → 吉祥物 → 資料庫 → 部署）。
- 後台管理頁不改；不串真實金流；不做手機 App、會員社群、養成成長、多可用區、CI/CD。
- 只用測試或假資料；僅內部示範，不公開上線。
- 程式碼放在 GitHub `chaoting-sun/inventrix`。

## 假設

- Q1–Q4 由使用者交給我決定，採推薦選項（1 元 = 1 點；10 秒 +10 點最多 3 坨；訂單照舊記金額另記點數；購物車存瀏覽器）。
- 商品圖片沿用現有圖片；AI 產生新圖的功能屬後台，不在本次範圍。

## 範圍外

多可用區、CodePipeline／CodeBuild、養成成長、後台改動、真實金流、手機 App、會員社群、公開上線與授權處理。
