# 使用者流程：塔麻可吉主題互動電商前台

依據：`ideation/intent-capture/intent-statement.md`（成功標準：瀏覽 → 加入購物車 → 下單，吉祥物互動可見）、`ideation/scope-definition/scope-document.md`（價值流）、`ideation/scope-definition/intent-backlog.md`（B1–B3）、`wireframes.md`（S1–S6）、`rough-mockups-questions.md`（Q1–Q2）。

## 主要流程（展示用）

```
[S1 首頁商品列表]
      |
      | 未登入？ ---- 是 ----> [S6 登入] ----+
      |                                     |
      v <-----------------------------------+
[S1 首頁，已登入]  便便開始隨機出現
      |
      | 點掉便便（重複）：+N ★、吉祥物開心
      v
[S2 商品頁] -- 加入購物車 --> 吉祥物開心、頁首購物車件數 +1
      |
      | （可回 S1 繼續逛、繼續點便便）
      v
[S3 購物車頁]
      |
      +-- 點數足夠 --> [ 用點數結帳 ] --> [S4 結帳成功] 吉祥物跳舞、扣點
      |                                        |
      |                                        v
      |                                  [S5 我的訂單]
      |
      +-- 點數不足 --> 顯示「還差 ★ N，去清便便吧！」 --> 回 S1 點便便
```

## 分支與例外

| 情境 | 處理 |
|------|------|
| 未登入時按「用點數結帳」 | 先到 S6 登入，登入後回到 S3 購物車 |
| 商品已售完 | S1 顯示「已售完」，S2 的「加入購物車」停用 |
| 購物車是空的 | S3 顯示「購物車空空的，去逛逛吧！」與回商品列表按鈕 |
| 點數不足 | S3 結帳按鈕停用，顯示還差多少點 |
| 一段時間沒有互動 | 右下角吉祥物變成「餓了」，有互動後回到待機 |
| 結帳時庫存不足或點數已被扣光 | 顯示錯誤訊息並留在 S3，購物車內容不變 |

## 資訊架構

```
TAMA SHOP
├── 商品（S1）
│   └── 商品頁（S2）
├── 購物車（S3）
│   └── 結帳成功（S4）
├── 我的訂單（S5，需登入）
└── 登入／註冊（S6）
（後台管理頁維持原樣）
```
